# tokenauth

安全方向小项目，`make test` 跑自检。

## 重放缓存

`NONCE_CACHE_CAP` 是缓存容量的硬上界（默认 10000），不是扩容阈值：

- **定容**：`auth_init` 一次性分配槽数组与哈希表，之后不再 `malloc`；
  恶意流量再多，内存也不增长（`cache_memory_fixed` 用 100 万次插入验证）。
- **淘汰最旧**：满员时淘汰最早插入的 nonce（FIFO）。命中不刷新年龄，
  因此插队重放无法把攻击者自己的旧记录续命。
- **O(1)**：槽数组按插入顺序串成链表，开放寻址哈希表 `nonce -> 槽位`，
  删除用 backward-shift（不用墓碑，探测链不会被反复污染的流量拖长）。
- **抗碰撞**：哈希带每进程随机盐（`/dev/urandom`），相邻或构造的 nonce
  不会挤进同一条探测链；`cache_probes_bounded*` 断言实测最长探测 < 64。
- **可验证**：小容量用例把淘汰顺序直接打印出来
  （`trace_evicted=10,11,12,13` / `trace_order=14,15,16,17,100,...`），
  另有结构不变量检查（每个存活槽在表中恰好出现一次、FIFO 链不漏不重），
  以及与独立哈希表参考实现（分离链接 + 链表 FIFO）逐条比对的结果。
- **延迟**：容量一万时，含 HMAC-SHA256 的完整校验中位数约 2 µs
  （`verify_ns_median`），缓存单次命中/插入约 0.4 µs；并对比容量 1k 与 10k
  的成本，确认不随容量增长。尾部（p99/max）会被 WSL2/CI 的抢占污染，
  只打印不断言；阈值按中位数与去掉最慢 1% 的截均值判定。
